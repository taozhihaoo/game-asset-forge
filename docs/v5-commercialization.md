# V5.4 — 商业化决策分析

Date: 2026-10-02 · 本文档是**分析与建议**，不是决定。决策权在用户（tazo/tao
zhihaoo）。结合 V1–V4 的实际产出与项目章程（local-first、确定性、离线优先）。

## 现状盘点（决策输入）

**资产**：四版本迭代的 monorepo（core 纯函数引擎 / CLI / Electron GUI / AI
层）、228→341 测试的确定性工程、五版本文档链、Godot/Unity 双引擎导出、
AI 建议层（mock/cloud 可插拔）。**技术差异化真实存在**：一条命令从乱表
到引擎资产 + 质量报告 + cutout 预览，这个完整度在开源工具里罕见。

**约束**：
- Spine 导出（若有）公开发布前需 Esoteric 书面确认（章程既有条款）；
- 用户背景：Godot/C#/卡牌 roguelite，Godot 生态是主场；
- 维护者是单人——商业化 = 承诺支持响应。

## 四个选项

### A. 纯 MIT 开源（现状）
- **利**：零法律成本、GitHub 传播最大化、Godot 社区友好（Godot 本身 MIT，
  生态工具默认预期 MIT）、简历/影响力资产。
- **弊**：无收入；被商业工具白嫖无追索；issue 支持是无底洞。
- **风险**：低。唯一注意：README 声明"AS IS"已有。

### B. 开源核心 + 付费 Pro
- **形态**：MIT 核心（现有全部）+ 闭源 Pro 插件（批处理 GUI、云 preset 同
  步、AI 云端配额打包）。
- **利**：收入与开源声誉并存；Pro 范围可伸缩；AI cloud 调用天然有成本，
  Pro 打包转售 API 额度是合理收费点。
- **弊**：需要两套发布/支持流程；单人力不支持；免费/付费边界会持续被挑战。
- **前置**：注册经营实体（税务）、支付通道（Gumroad/LemonSqueezy）。

### C. 双许可（GPL 核心 / 商业许可）
- **利**：强制商业用户付费的法律抓手。
- **弊**：与 MIT 既有历史冲突（需重许可，所有既有贡献者同意）；GPL 会把
  Godot 用户吓跑（Godot 生态对 GPL 工具链的下游污染顾虑真实存在）；单人
  维护者执行双许可的法律成本不成比例。**不推荐**。

### D. 一次性付费独立软件（闭源）
- **利**：定价简单（对标 Aseprite $19.99 一次买断 + 全平台）；独立开发者
  对买断制好感度高；代码可闭源省去合规负担。
- **弊**：放弃已积累的开源势能；从 0 建立付费信任；demo→付费转化漏斗
  需要营销投入。

## 建议

**近期（6 个月）：A（保持 MIT），但做三件事**
1. README 加 "Support the project"（GitHub Sponsors）——零成本试水付费意愿；
2. 积累 star/user evidence——商业化决策需要需求证明，不是现在拍脑袋；
3. AI cloud 调用永远 BYO-key（bring your own key），把成本留在用户侧。

**触发条件（满足任一再重估 B/D）**：GitHub star > 1k 且月度 issue 流量
> 维护带宽；或出现企业/工作室询问商业许可的真实邮件（现在一封都没有）。

**永不**：C 双许可（与 Godot 生态相性最差）；把 AI cloud 做成强制订阅
（违背 local-first 章程）。

## 与 V4 停止条款的关系

V4 文档说"V4 保持原型级，V5 再决定商业化"——本文档即该决策的输入。
V5 的三项技术兑现（CDT/patch-match/AnimationPlayer）在 A 与 B 下都是
MIT 开源的一部分；**技术路线不依赖商业决策**，这也是先写代码后拍板的
原因。
